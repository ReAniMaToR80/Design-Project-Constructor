# Конструктор БС — ядро на C++17

Ядро автоматизированного конструктора проектов базовых станций (issue #1).
Чистый C++17 (собирается и в режиме C++20), без внешних зависимостей, без
макросов; GCC / Clang / MSVC. Ядро — статическая библиотека `bsc_core`,
пригодная для подключения к GUI; `bs_constructor` — консольная оболочка.

## Архитектура (L ↦ L²)

Все знания о регламентах хранятся как связи-дуплеты `index → (source, target)`
(`LinksStore`). Измерения ортогональны и задаются перечислениями (`Types.h`):

| Измерение | Значения |
|---|---|
| `Operator` | МТС, Т2, Вымпелком, Мегафон |
| `PositionType` | Крышная, Наземная АМС |
| `Aspect` → `Element` | Кабельная трасса → Фидер / Оптика; Аппаратная → Выгородка / Контейнер / ТКШ; Конструктив КМ → Трубостойка кастомная / Трипод разгрузочный |
| `Section` | ТХ, КМ, ЭМ, МЗ |

Каждое измерение — точка (связь сама на себя). Факты — вложенные дуплеты
(пара, маркер / позиция спецификации):

```
((оператор, элемент), allowed)      — регламент оператора допускает элемент
((тип площадки, элемент), compatible) — элемент совместим с конструктивом площадки
((тип площадки, элемент), default)  — типовое решение по аспекту
((оператор, элемент), item)         — позиции спецификации оператора (ТХ/ЭМ/КМ/МЗ)
((оператор, тип площадки), item)    — АФУ, заземление и т. п.
((тип площадки, элемент), item)     — крепления, кабельросты, молниезащита
```

Спецификация проекта = объединение позиций по связям выбранных
`(оператор, тип площадки, элементы)`. Поэтому при переключении оператора
меняются ровно позиции, связанные с оператором, а позиции площадки и данные
объекта (номер БС, выбор элементов) сохраняются — это проверяют тесты
`constructor/switching operators relinks the specification`.

| Файл | Назначение |
|---|---|
| `include/LinksStore.h` | хранилище связей (точки, дуплеты, поиск) |
| `include/LinkMatrix.h`, `src/TypicalSolutions.cpp` | матрица связей и база типовых решений |
| `include/SafeString.h` | `safeSet`, нормализация UTF-8, регистр, числа |
| `include/ActParser.h` | парсер акта / лога: номер БС, тип площадки, выбор элементов |
| `include/Validator.h` | конфликты: регламент, совместимость, нагрузка на КМ, длина фидера |
| `include/BSConstructor.h` | фасад: `loadAct`, `configure`, `switchOperator`, `build` |
| `include/Report.h` | CSV-спецификация, текст ТЗ, атрибуты штампа dwg |
| `app/main.cpp` | консольная утилита |
| `tests/` | модульные тесты (собственный раннер без макросов) |

### Проверки (`Project::conflicts`)

| Код | Уровень | Условие |
|---|---|---|
| `E_NO_SITE_ID`, `E_NO_OPERATOR`, `E_NO_POSITION`, `E_NO_SECTORS` | ошибка | в акте нет обязательных данных |
| `E_NO_CHOICE` | ошибка | аспект не выбран и нет типового решения |
| `E_OPERATOR_REGULATION` | ошибка | элемент не предусмотрен регламентом оператора |
| `E_POSITION_INCOMPATIBLE` | ошибка | контейнер на кровле; выгородка или трипод на АМС |
| `E_KM_OVERLOAD` | ошибка | масса оборудования на единицу КМ × 1,3 > несущей способности |
| `W_FEEDER_LENGTH` | предупреждение | фидерная трасса длиннее 50 м |
| `I_DEFAULT_APPLIED`, `I_KM_LOAD` | информация | применено типовое решение; запас по несущей способности |

Пример: МТС на трубостойке — (22 + 2·25)·1,3 = 93,6 кг ≤ 120 кг; после
переключения на Мегафон — (35 + 2·30)·1,3 = 123,5 кг > 120 кг → `E_KM_OVERLOAD`.

### Безопасная работа со строками

`text::safeSet(dst, src, maxBytes)` — `noexcept`: при `nullptr` или ошибке
`dst` не меняется; чтение ограничено `maxBytes` (буфер без завершающего нуля
не приводит к выходу за границу); некорректный UTF-8 заменяется на `?`,
управляющие символы — на пробелы; обрезка не разрывает многобайтные символы.
Парсер принимает `(nullptr, size)`, обрезает акты больше 1 МиБ и пишет
предупреждения вместо исключений.

## Формат акта

Строки `Ключ: значение` или `Ключ = значение`, также JSON-вывод скрипта
`input_parser` (`"Site_ID": "78-04546"`) и сводка трекера через `|`.
Ключи распознаются без учёта регистра (рус./англ.: «Номер БС», `Site_ID`,
«Тип площадки», `Position_Type`, «Кабельная трасса», «Аппаратная»,
`Cabinet_Type`, «Конструктив КМ», «Высота подвеса», «Количество секторов»,
«Длина кабельной трассы», «Оператор»). Если номер БС или оператор не указаны
полем, они ищутся в свободном тексте («БС №78-04546», «ПАО МТС»; при
упоминании нескольких операторов оператор не угадывается). См. `examples/`.

## Сборка и запуск

```sh
cmake -S cpp -B build -DBSC_WARNINGS_AS_ERRORS=ON   # -DBSC_CXX_STANDARD=20 для C++20
cmake --build build --config Release
ctest --test-dir build --build-config Release --output-on-failure

build/bs_constructor --dwg                                     # встроенный демо-акт
build/bs_constructor cpp/examples/act_mts_ground.txt --switch MEGAFON --csv spec.csv
```

Код возврата: 0 — проект корректен, 2 — есть конфликты, 1 — ошибка
аргументов / ввода-вывода. В Windows для вывода кириллицы в консоль выполните
`chcp 65001` (исходники компилируются MSVC с `/utf-8`).

## Использование из GUI

```cpp
bsc::BSConstructor constructor;                       // общая типовая матрица
const bsc::Project& p = constructor.loadAct(actText); // или configure(SiteConfiguration)
for (const auto& c : p.conflicts) { /* подсветить c.code / c.message */ }
constructor.switchOperator(bsc::Operator::Megafon);   // пересборка по связям
std::string csv = bsc::specificationCsv(*constructor.current());
```

## Допущения

Номенклатура, массы и несущие способности в `src/TypicalSolutions.cpp` —
**шаблон-заглушка**: позиции МТС взяты из существующих скриптов проекта
(Huawei RRU5502, Broadradio, Интеркросс Тип 5, Кр-1, КУСИЛнг-FRHF 2х6), остальное
— условные значения. Их нужно заменить действующими редакциями регламентов
операторов; меняется только этот файл. Ограничения регламента вводятся вызовом
`allow()` только для допустимых элементов (пример — тест
`validation/operator regulation`). Коэффициент 1,3 и предел фидера 50 м заданы
константами в `Validator.h`.
